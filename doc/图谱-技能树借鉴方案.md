# 图谱落地方案（Android 手机端）：借鉴 cs-math-skill-tree

> 参考项目：GitHub [zeroa234/cs-math-skill-tree](https://github.com/zeroa234/cs-math-skill-tree)（MIT，**纯静态网页**）。
> 本文是其核心机制的**手机端落地方案**。参考项目是宽屏网页（左侧栏 + 大画布），照搬布局在竖屏手机上不成立，所有交互已改为知境现有的手机端模式。

> **落地状态（2026-11-16）**：P0 已实现 —— `kg/SkillProgress.kt`（三态 + 解锁数，纯派生）+
> 结构图节点状态色/图标 + 统计行 `可学 N` / `✓ x/y` 两个 chip + 两段式底部面板。
> P1 的「选中链路强化」以现有选中高亮代替（不画祖先闭包：跨屏链路在竖屏上反而更难读），
> 目标模式、点亮动效未做；P2 全部未做。

## 一、手机端现状与适配总原则

当前图谱页（`GraphScreen.kt`）的形态：顶部返回栏 + 设置 → 视图切换 chips（卡片流/树视图）+ 搜索 → 统计行（"易混淆 2 · 未探测 27"）→ 树视图 Canvas（pan/zoom）→ 点击卡片弹出**底部详情 sheet**（ConditionProbeSheet 同模式）。

适配总原则（来自参考项目的机制、换成手机端载体）：

| 参考项目（网页） | 手机端做法 | 结论 |
|---|---|---|
| 左侧"现在能学"面板 | 统计行加一枚摘要 chip，点开 `ModalBottomSheet` 列表 | ✅ 复用现有 sheet 模式 |
| 顶部大进度条 | 统计行追加紧凑 chip："✓ 14/22" | ✅ 不新增顶栏层级 |
| 左栏编号学习清单（目标模式） | 卡片详情 sheet 菜单里"设为目标"；清单用底部面板 + 树上 ⭐ 标记 | ✅ |
| localStorage 导出/导入 | Android SAF（`CreateDocument`/`OpenDocument`） | ✅ 替代方案见 P2 |
| 鼠标悬停/精确点击 | 触控目标 ≥48dp、选中节点自动居中放大 | ⚠️ 需专门处理，见 P1 |

**侧边栏在手机端不直接可用**——竖屏宽度放不下常驻侧栏，且会挤压树视图横移空间。全部改为"摘要 chip + 底部 sheet"两段式：平时只占一行，要看详情才展开。

## 二、P0：卡片三态状态机 + "现在能学"（核心，纯派生层）

1. **新增 `SkillProgress.kt`**（`app/.../kg/`，纯 Kotlin 无 Android 依赖，配套单元测试）：
   - 输入 `MergedGraph`（GraphAssembler.merge 的产物）+ `kgStates` 的命题状态。
   - **卡片级点亮**：把 `kg_claim_state` 的四态聚合到卡片 → 实际落地规则：卡内 ≥80% 命题**已探测**（VERIFIED 或 MASTERED）且**没有 CONFUSED** 判"已点亮"。
     原方案写的"≥80% MASTERED"被实测否掉了：一轮下钻每条命题只判一次，`ProbeRules` 只给 VERIFIED（连续两次才 MASTERED），按原规则答完整张卡也点不亮，全图会卡死在 1.1。阈值放常量 `SkillProgress.LIT_PROBED_RATIO`。
   - **三态判定**：`LIT`（已点亮）/ `READY`（所有 required 前置卡片已点亮，且自身非 LIT）/ `LOCKED`（存在未点亮的 required 前置）。
   - **后续计数**：`downstreamCount(cardId)` = 直接和间接解锁的卡片数，用于"现在能学"排序（参考项目的"后续 44"）。
   - recommended 前置**不参与**判定（"只提示，不挡路"）。
2. **"现在能学"入口（手机端形态）**：
   - 统计行（"易混淆 2 · 未探测 27"）追加 chip：`可学 N ▸`，N = READY 数。
   - 点击弹出 `ModalBottomSheet`：READY 卡片列表，按 downstreamCount 降序，每项显示缩略名 + "后续 N"；点击即关闭 sheet 并定位节点（复用现有 `GraphFocus`，顺带居中放大）。
   - **首版不做横滑 chips 常驻**：树视图横向空间宝贵，常驻条会挤压画布；sheet 按需展开是本项目已有交互（卡片详情、条件探测都是 sheet），一致且省屏。
3. **进度 chip**：统计行追加 `✓ x/y`（x=已点亮卡片，y=卡片总数），点击弹出三态分布明细（已点亮/可学/未解锁各自数量）。
4. **三态视觉**：卡片边框色 + 图标（✓ / ⊕ / 🔒）双编码；树上节点小、缩放后颜色不可靠，**图标必须保留**。
5. **TalkBack**：节点 `contentDescription` 带上状态（"矩阵乘法，已点亮"）。

不改 Room：三态全部实时派生，与"状态不进图谱数据、只派生"的架构约定一致（GraphAssembler 已有 badgeStatus 先例）。

## 三、P1：选中链路强化 + 目标模式（手机端手势适配）

1. **选中高亮升级**（`GraphTreeView.kt`）：
   - 实线高亮整条 required 前置链（祖先闭包）；**绿色高亮直接解锁的后续（子孙一层）**；未在链路上的边降透明度。
   - **手机端适配**：竖屏下可视节点少，高亮链路常超出屏幕——选中节点时把节点居中；链路在屏幕外的部分用节点角标提示（如"上方还有 3 个前置"）。
   - 点击与 pan/zoom 的区分沿用现有 `detectTransformGestures` 判定，不新增手势。
2. **设为目标模式**：
   - 入口：卡片详情 sheet 的操作区加"设为目标 ⭐"。**不用长按菜单**——长按在触屏上可发现性差、易误触（与 pan 冲突），sheet 内显式按钮更可靠。
   - 呈现：目标节点树上加 ⭐ 角标；"待点清单"（拓扑序编号）与"现在能学"共用同一个底部面板，chip 变为 `目标：矩阵乘法 ▸`。
   - 内存态即可，不落库；换主题/退出即清除。
3. **点亮动效**：READY→LIT 时对该节点做一次描边扩散动画（`animateFloatAsState`，~300ms）。手机端只动单个节点、不做全图波纹——低端机 Canvas 全图动画会掉帧。

## 四、P2：导出/导入、生成图谱打通、可选化

1. **进度导出/导入（Android SAF，替代网页的 localStorage）**：
   - 导出：`kg_claim_state` / `kg_condition_probe` 序列化 JSON → `CreateDocument("application/json")` 让用户选保存位置；入口放图谱页设置 sheet。
   - 导入：`OpenDocument` 选取后**先整包校验再写回**，失败整包拒绝、不做部分导入。
   - 价值：规避 Room `fallbackToDestructiveMigration` 升级清库丢进度。
2. **生成图谱接入同一状态机**：`kg_generated_prerequisite` 的 required 边同样参与三态判定（`SkillProgress` 输入是 `MergedGraph`，天然覆盖生成树）。首版生成图谱只显示计数不门控。
3. **低置信度卡片"可选化"**：生成图谱中 `verified=false`（模型撰写）的卡片用降级样式（虚线框 + 更淡底色），与原文逐字截取的主干卡片区分。纯渲染分支，字段已存在，无需改 schema。
4. **学习资源字段**（可选、改动最大，**不照搬**参考项目 192 条章节级双语路线——重编辑成本不成比例）：若做，卡片详情 sheet 加"去哪学"链接列表，手机端用 `Intent`/Custom Tabs 打开浏览器；来源为用户手工添加或导入时模型抽取。

## 五、参考项目里手机端直接不适用、已剔除的部分

- **常驻左侧栏**（现在能学面板、编号清单）：竖屏放不下 → 改 chip + 底部 sheet。
- **hover 悬停预览**：手机无 hover → 一切信息进点击后的 sheet。
- **URL hash 路由/分享链接**：App 是单 Activity 枚举导航 → 不需要。
- **浏览器 localStorage**：改 SAF。
- **键盘无障碍**（Tab 遍历、快捷键）：退化为触控目标 ≥48dp + TalkBack 语义。
- **elkjs/d3/markmap**：App 端本就是 Compose Canvas 自绘，无引入必要。

## 七、风险与约定

- **门控不做"写死"**：三态只是派生展示 + 建议顺序，不阻止点击 LOCKED 卡片查看内容（详情 sheet 本来就开放）。
- **掌握度阈值**放常量便于调参；首版 80% MASTERED，后续可换成探测正确率加权。
- 生成图谱的 required 边质量参差（`OutlineBuilder` 兜底生成），首版只计数不门控。
- `GraphModeStore`（OFFLINE/CLOUD_ENHANCED）与状态机无关，不要耦合。
- **线型语义冻结**：实线=必须前置、虚线=推荐前置不变；绿线是新增线型，不得复用现有实/虚线。
- **竖屏空间预算**：统计行是唯一的常驻新增区（chips 属于现有行的扩展），其余信息全部按需进 sheet；任何改动不得让树视图可视高度变矮。
- **性能**：动效仅限单节点；`SkillProgress` 在每次进入图谱页/状态变化时重算一次（缓存结果），不在每帧 Canvas 绘制里调用。
