# 广度图谱：通用提示词 + 本地算法

> 对应代码：`app/src/main/java/com/example/zhijing/kg/{CloudOutlineExtractor,OutlineBuilder,CrossLinker}.kt`
> 提示词文档：`kg/prompts/extract_outline.md`
> 与深度提示词 `extract_claims.md` 严格分工

## 一、为什么拆成两个提示词

原来只有一个 `extract_claims.md`，它同时干了「抽断言」「抽条件」「抽边」三件事——
全是**深度**的事。而广度需要的「这个主题由哪些部分组成」，**没有任何提示词**，
24 个大纲节点和 22 张卡片全是手写的。

拆开后：

| | 广度（本页） | 深度（`extract_claims.md`） |
|---|---|---|
| 回答 | 这个主题**由哪些部分**组成 | 这个点**到底是什么** |
| 产出 | 块的标题、摘要、原文区间 | 命题、条件、错点归因 |
| 禁止产出 | 任何判断（成立/不成立） | 任何组织性内容 |

## 二、通用提示词：不含任何领域词

**核心要求**：换任何领域（法律、医学、历史），提示词一个字都不改。

一旦出现领域词（「前馈网络」「注意力」「Linear」），会产生两种偏差：

1. 模型以为「要抽这种内容」，换领域就不灵；
2. 模型把示例的结构当成领域约定，而非输出格式。

因此 `extract_outline.md` 的示例全部用抽象占位符。

**`CloudOutlineExtractorTest` 里有一条断言守在这一点上**：扫描 `SYSTEM_PROMPT`，
出现任一领域词（前馈/张量/注意力/Linear/Softmax/token 等 25 个）即失败。

## 三、分工：模型只做减法，本地做加法

| 环节 | 谁做 | 怎么算 |
|---|---|---|
| 切出「有哪些部分」 | **模型** | 输出 `title` / `summary` / `bodyStart` / `bodyEnd` |
| 层级（谁是谁的父） | **本地** `OutlineBuilder` | 从标题编号推 |
| 正文 | **本地** | `content.substring(start, end)` 逐字截取 |
| 交叉链接 | **本地** `CrossLinker` | 正文词共现 |

三个好处：

- **零失真**：正文就是原文，模型改不了内容；
- **零幻觉**：模型只指认「这段属于哪部分」，不生成事实；
- **可复现**：除模型切分外，其余全部确定性。

## 四、模型输出

```json
{
  "blocks": [
    {"title": "主题A", "summary": "一句话概括", "bodyStart": 0, "bodyEnd": 240},
    {"title": "主题A的子项", "summary": "一句话概括", "bodyStart": 240, "bodyEnd": 620}
  ]
}
```

**没有 `path`、没有 `level`、没有 `parent`** —— 这些是本地算的。

## 五、本地算法

### 5.1 层级推断（`OutlineBuilder`）

按优先级：

1. **标题编号**：`1` / `1.2` / `1.2.3` / `一、` / `（一）` / `第X章` → 按编号深度定 level
2. **无编号**：首块为根，其余同级
3. 上限 3 级（与 `graph.schema.json` 一致）

父子关系：找**最近的、层级恰好小一级**的前驱作为父节点。

不做自动聚类 —— 把「哪些块同类」交给模型的分块顺序，比算法猜更稳。

### 5.2 区间校验（丢弃优先）

| 情况 | 处理 |
|---|---|
| 越界（`end > 长度`） | 丢弃该块 |
| 倒置（`start >= end`） | 丢弃该块 |
| 与前一块重叠 | 丢弃该块 |
| 缺 `title` | 丢弃该块 |

**宁可少一块，不截出错字。**

### 5.3 交叉链接（`CrossLinker`）

1. 分词：中文 2 字滑窗 + 英文 `[a-zA-Z][a-zA-Z0-9_]+`
2. 去掉停用词（含「这是」「一个」「可以」等虚词组合）
3. Jaccard 相似度 = 共享词 / 并集
4. 阈值 0.14，每卡最多 5 条，按权重降序

用 Jaccard 而不是「共享词数」：后者会让长卡片无差别连满。

## 六、修掉的一个真 Bug

**`splitObjects` 死循环。**

数组体里混入非对象元素（模型偶尔把字符串或数字塞进来）时：

```kotlin
if (body[i] != '{') {
    while (i < body.length && body[i] != ',') i++
    continue   // ← 若 body[i] 恰好是 ','，内层 while 立即退出，i 不前进
}
```

外层 `while` 再次看到同一个逗号，**永久循环**。测试表现为整个测试进程卡死，
`jstack` 定位到 `CloudOutlineExtractor.kt:249` 后修复：跳过元素时**吃掉逗号**。

`ClaimOutputParser` 早期也踩过这个坑，已通过在分支前先处理 `i++` 规避。
