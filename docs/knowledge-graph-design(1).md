# 广度知识图谱与深度探索图谱：设计总结

> 本文整理两张图谱的核心目标、形态、其间的数据契约，以及边界约束。
>
> **一句话概括：广度图谱负责"覆盖"——让人知道一个主题由哪些部分组成；深度图谱负责"穿透"——让人真正理解其中一个点。深度依附于广度，靠共享命题 ID 与状态回写连接。**

## 一、总览

### 核心目标：覆盖 vs 穿透

两张图谱的差异，首先不在形态和操作，而在于各自要回答的根本问题：

| | 广度图谱 | 深度图谱 |
| --- | --- | --- |
| **核心问题** | 这个主题**由哪些部分**组成 | 这个知识点**到底是什么** |
| **本质** | **覆盖**：范围完整、边界清楚 | **穿透**：理解到底、知道边界 |
| **成功标准** | 用户能说出这个主题的**全貌** | 用户能**独立判断**，并知道**边界在哪** |
| **失败的样子** | 有遗漏、结构混乱 | 能复述、不能判断、不知边界 |
| **单位** | 主题、卡片 | 单个知识点（命题） |
| **尺度** | **横向铺开** | **纵向钻透** |

两条推论，是整套设计的地基：

1. **检查标准不同。** 广度只要用户读完能复述结构就算成功——要求低，但覆盖面广；深度必须用户**自己做出判断**才算成功——范围窄，但要求高。因为"理解"唯一可验证的证据，就是用户能否在新条件下独立做判断。所以深度图谱**必须有判断面板**，那是"理解"唯一能落地的检验形式；广度图谱则不需要用户下判断，有阅读就够。
2. **工作量分配不同。** 广度决定用户**知道多少**，深度决定用户**看透几个**。两者不是同一种工作的放大缩小，不能互相替代。

### 对照表

| 维度 | 广度知识图谱 | 深度探索图谱 |
| --- | --- | --- |
| 第一目标 | **读**：信息量、准确、可读 | **判**：先判断、再撞错、再知道错在哪 |
| 核心问题 | 这个主题**由哪些部分**组成 | 这个知识点**到底是什么** |
| 本质 | **覆盖** | **穿透** |
| 形态 | 分层大纲 + 卡片 + 交叉链接 | 命题—边—条件 + 判断面板 + 状态汇总 |
| 不是 | **不是节点-边图** | 不是独立产品，不是并列结构 |
| 用户动作 | 读、查、定位 | 判、拨、撞错 |
| 组织单位 | 大纲节点 + 叶子卡片 | 命题（带条件的边） |
| 定位 | 阅读与定位的容器 | 依附在叶子卡片上的判断训练场 |

核心判断：**价值在"判"，不在"图"。** 如果产品被记住的是"一张用来判断的图"，它就成立；如果被感觉成"加了测试的思维导图"，它就失败。两者的距离只在"撞错"做得够不够狠。

## 二、广度知识图谱

### 核心目标：让用户知道这个主题都有什么

广度图谱要解决的是**范围问题**：用户读完以后，知道这个主题由哪些部分构成、各部分之间怎么划分、自己现在处在哪一块、还有哪一块没碰过。

判定标准是：**用户读完一张广度卡片，能不能说出这个主题的完整构成。**

所以它真正的要求是**结构完整、边界清楚、没有遗漏**：

- 大纲的价值是**切分出"有哪些部分"**，不是把条目排出来；
- 卡片的价值是**把一块讲清楚到自己知道它是什么**；
- 交叉链接的价值是**让用户知道块与块之间的关系**。

这三样都是"覆盖性"的工作，产出的是对全貌的把握。

> 注意：广度图谱回答的是"由哪些部分组成"，**不替深度图谱回答"这个点到底是什么"**。

### 形态

```
分层大纲
 └─ 章 / 节 / 主题        （分类节点：只负责组织，不做判断）
     └─ 卡片              （可横向交叉链接）
         └─ 叶子卡片      ← 下钻入口在此
```

### 组成要素

| 要素 | 作用 | 约束 |
| --- | --- | --- |
| 分层大纲 | 提供结构感与定位 | 分类节点不参与判断，不能下钻 |
| 卡片 | 承载一段完整可读的内容 | 每张卡是一个可独立阅读的单元 |
| 交叉链接 | 卡片间的横向指引 | **必须封顶（建议 3–5 条）并排序**，否则退化成节点图 |
| 叶子卡片 | 大纲末端 + 命题挂载点 | 一个命题只归**一张**叶子卡片（主归属） |

### 状态表现

广度图谱**不自己产生判断状态**，只承接深度图谱回写后的摘要，表现为：

- 卡片角标：未探测 / 已掌握 / 易混淆 / 已验证
- 易错点注记：来自深度侧撞错时暴露的误解
- 次要信息：最近探测时间

## 三、深度探索图谱

### 核心目标：让用户真正理解一个知识点

深度图谱要解决的是**穿透问题**：对**某一个**知识点，用户不是"能复述"，而是"能判断、能推到条件边界、知道自己错在哪"。

判定标准是：**用户把这个点单独拿出来判断时，能不靠原文、自己推出结论，并且知道它在什么条件下不成立。**

所以它真正的要求是**边界清楚、因果清楚**：

- **条件**是划出"这个知识点的**适用范围**"；
- **边**是说明"它**依赖什么、影响什么**"；
- **判断面板**是让用户**先自己暴露理解偏差**；
- **撞错**是**定位偏差落在哪条连接上**。

### 深度由三条定义

一个知识点"理解透了"，就是指用户能说清这三条。三条说不清，即使背下定义，也不叫理解：

1. **它依赖什么** —— 上游条件；
2. **它影响什么** —— 下游结果；
3. **它在什么条件下不成立** —— 边界与反例。

因此，深度图谱上的边本质是"**依赖与影响**"，条件本质是"**适用范围**"，撞错撞的正是"**边界判错**"或"**依赖判错**"。

（以模型架构为例：`Linear → ReLU → Linear → Softmax → CrossEntropy` 的每一层是一条命题，"层与层之间能不能接上"的判据就是边上的条件，如形状依赖、值域依赖、统计量依赖、梯度路径依赖、语义依赖。用户说"ReLU 后面可以直接接 Softmax"，形状对得上不报错，错在语义依赖——他撞的就是"依赖判错"。）

### 定位

**用户先判断，再撞错，再知道错在哪。** 它的价值是让"我到底信不信这条、什么条件下它不成立"变成可操作的动作。

它依附于广度图谱的叶子卡片，**没有独立入口、独立目录或独立 URL**。

### 形态

```
命题
 ├─ 判断面板        一句话命题 + 对 / 错（成立 / 不成立）
 ├─ 边（带条件）    命题之间的依赖与边界
 └─ 状态汇总        未探测 / 已掌握 / 易混淆 / 已验证
```

### 组成要素

| 要素 | 说明 |
| --- | --- |
| 命题 | 一句话可判真假的断言，全库唯一 ID |
| 边 | 命题之间的关系，**边必须带条件**（成立前提、边界、反例） |
| 判断面板 | 先判后揭示；条件边藏在撞错之后，不在第一屏展开 |
| 状态汇总 | 收敛后的结果，而非逐次作答明细 |

### 状态模型

| 状态 | 含义 |
| --- | --- |
| 未探测 | 从未判断过 |
| 已验证 | 多次判对，状态收敛 |
| 已掌握 | 判对且置信度充足 |
| 易混淆 | **已探测，但易错未解除** |

注意：**"已探测"不等于"已掌握"**。"撞错"之后存在"已纠正"和"仍易错"两种状态，二者必须在状态汇总里区分，否则回写到广度侧就会失真。

### 第一屏原则

深度图谱是一个**全新动作**，用户没有参照物。因此第一屏必须是：

> 一句话命题 + 两个按钮（对 / 错，或成立 / 不成立）

把条件边和状态汇总藏在撞错之后。这一条既是产品原则，也反向约束数据模型：**条件不能在第一屏就被全部铺开**。

## 四、两者的连接方式

### 结构关系

```
广度知识图谱（Read：读、查、定位）
  分层大纲 → 卡片 → 交叉链接
                      │
                      │ 叶子卡片 ──下钻──► 深度探索图谱（Judge：判、拨、撞错）
                      │                      命题—边—条件 + 判断面板 + 状态汇总
                      ▲                              │
                      └──────── 状态回写 ◄───────────┘
```

**深度图谱是广度图谱叶子卡片上的下钻入口，不是并列结构。**

### 数据契约：共享命题 ID

命题是**唯一可寻址的实体**，两个视图只是它的两个渲染面：

```yaml
claim:
  id:            # 全库唯一、稳定不变、带语义前缀
  statement:     # 一句话命题
  conditions: [] # 成立条件 / 边界 / 反例
  links: []      # 交叉链接：指向其他 claim 或大纲节点

  breadth:       # 广度视图所需
    outline_path:  # 主归属卡
    card_summary:
    leaf_content:

  depth:         # 深度视图所需
    edges: []      # 带条件的边
    judgement_panel:
    probe_state:
```

要点：

- **两边不各存一份命题**。广度侧复制一份放进深度图谱，两份迟早不一致。
- **ID 规范必须先定**，并把 ID 当作发布物对待；ID 一旦改名，交叉链接与回写状态全部失效。
- **分类节点不需要 ID 级的命题身份**。大纲树是阅读结构，命题图是判断结构，二者通过叶子卡片 ↔ 命题的映射对接。

### 回写：只回写收敛后的摘要

| 回写字段 | 含义 | 广度侧表现 |
| --- | --- | --- |
| `probe_status` | 未探测 / 已验证 / 已掌握 / 易混淆 | 卡片角标（颜色或图标） |
| `last_probed_at` | 最近探测时间 | 次要文字 / 悬停 |
| `misconceptions[]` | 撞错时暴露的误解 | **易错点注记（最有价值）** |
| `confidence` | 判断置信度 | 可选，不做成进度条 |

**不回写**：逐题作答记录、每次拨动的中间状态。这些只存在于深度侧。

回写的意义不在"多一个状态点"，而在让广度卡片**变厚**——"别人在这里容易撞错什么"是高价值、可读的信息。

### 回写的方式：派生而非存储

广度侧**不存储**判断状态，渲染时从深度侧聚合。

- 优点：单一真相源，不会出现两套数据打架。
- 代价：广度页面需要一次查询，需在构建期预计算或加缓存。

## 五、核心约束

1. **命题 ID 是唯一主键**（单一真相源）。
2. **深度图谱是下钻，不是并列结构**：无独立入口、无独立目录，退出后回到原卡片。
3. **一个命题只有一个主归属卡**：可以有多入口，但只有一个"主归属"，否则回写状态时"该标在哪"会产生歧义。
4. **回写是摘要而非明细**：只回写收敛后的 4 类字段。
5. **回写走派生**：广度侧不存状态，从深度侧聚合。
6. **区分"撞错后纠正"与"仍易错"**：状态汇总必须能表达"已探测但易错未解除"。
7. **广度侧交叉链接封顶**：每卡 3–5 条并排序，防止退化成节点图。
8. **深度侧条件不在第一屏展开**：第一屏只有命题 + 两个按钮。

## 六、风险与未决事项

### 风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| **撞错体验失败** | 条件太可见 → 白点一下；太隐蔽 → 判错也看不出错在哪 | 条件要"宽到容易判错、窄到能自己定位错点" |
| **内容成本被低估** | 命题+条件+误概念+解释，产量远低于写讲解 | 先做垂直领域的一小簇命题，跑通闭环 |
| **没有先例 = 没有参照物** | 首次动作陌生，用户点进去不知道干什么 | 第一屏极简，两按钮 |
| **判断状态变成装饰品** | 回写状态不被看、或看了不知做什么 | 状态必须驱动动作（易错先读 / 已掌握跳过） |
| **数据重复** | 两边各存一份命题与状态 | 命题与状态只存一份 |
| **入口并列** | 从全局入口进深度图谱，绕开叶子卡片 | 取消全局入口 |
| **ID 漂移** | 改名导致链接与状态失效 | 先定 ID 规范，按发布物对待 |
| **归属歧义** | 命题归多张卡导致状态标不准 | 唯一主归属 |

### 市场位置

零件都有先例，组合几乎没有先例：

| 类别 | 代表形态 | 对应哪个特征 | 缺什么 |
| --- | --- | --- | --- |
| 论证 / 论辩地图 | 主张 + 支撑 / 反驳 | 命题作单位、部分"先判被反驳" | 没有学习者状态，没有广度阅读容器 |
| 诊断式自适应测评 | 先测后教、错了给解释 | 判断面板、状态汇总 | 单位是题，边不带条件 |
| 知识追踪 / 记忆系统 | 熟练度、掌握度面板 | 状态汇总 | 绑定题目，无命题—条件结构 |
| 概念图谱 / 因果图工具 | 断言为单位的结构图 | 命题与边的技术形态 | 面向分析而非判断，无阅读大纲 |
| 大纲型学习平台 | 课程 / 文档平台 | 广度那一半 | 没有判断层 |

**结论：深度图谱作为整体形态未见成熟先例，但它由已验证的零件组成。** 风险不在"能不能做"，而在"组合契约会不会散架"。

### 未决事项

- [ ] **命题粒度**：一条命题是"一句话可判真假"，还是允许一段带多个论点的论述？（决定判断面板形态）
- [ ] **广度侧状态**：派生（倾向）还是存储？派生需评估查询 / 预计算成本。
- [ ] **跨卡共享命题**：同一命题能否被多张叶子卡片引用？若可以，"主归属 + 从属引用"模型需提前设计。
- [ ] **深度状态汇总的位置**：只在深度视图顶部，还是也体现在广度大纲的某一层？
- [ ] **ID 命名规范**：语义层级前缀 + 哈希，还是纯流水号？
- [ ] **撞错体验的评判标准**：条件可见性、错点定位、失败提示写法，需整理成可检查清单。

## 附：一句话总结

- **广度图谱**：让用户看清一个主题**由哪些部分组成**——不遗漏、不混乱。
- **深度图谱**：让用户钻透**其中一个点**——能独立判断、知道边界、清楚错在哪。
- **合起来**：广度规定"有哪些"，深度保证"每一个都能看透"；广度决定用户**知道多少**，深度决定用户**看透几个**。读的时候知道自己在哪，判的时候知道自己在读什么，判断的结果回到读过的地方。
