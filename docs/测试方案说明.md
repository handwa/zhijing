# 测试方案说明 —— 知境

> 覆盖两部分：`kg/` 知识图谱脚本（Python）与 `ui/mock/` UI 原型（HTML/JS）。
> 两者都**零第三方依赖**，本机即可跑，失败非 0 退出，可直接接 CI。

---

## 一、知识图谱脚本测试（`kg/tests/`）

用 Python 标准库 `unittest`，不引 pytest（脚本本身零依赖，引入 pytest 会破坏「纯标准库」的交付承诺）。

### 运行

```bash
cd zhijing
python -m unittest discover -s kg/tests -v
# 或只跑某一部分
python -m unittest kg.tests.test_kg_model -v
```

### 三个测试文件

| 文件 | 测什么 | 条数 |
|---|---|---|
| `test_kg_model.py` | 文本规范化 / 哈希稳定性 / ID 生成校验 / 标注块解析器 | 26 |
| `test_validate_rules.py` | 校验器 10 条规则的反向注入（证明每条规则非恒真）+ 正向全过 | 12 |
| `test_pipeline.py` | 端到端 build→validate→export 链路 + counts 锚点 + 幂等性 | 5 |

### 关键设计

- **counts 回归锚点**：`outline 24 / card 22 / claim 35 / entity 44 / edge 16`。任何意外增删节点都会被 `test_counts_anchor` 抓住，防止语料被静默破坏。
- **反向注入**：`test_validate_rules` 复用 `selftest.py` 的注入器，向 graph 注入「悬空边 / 缺 boundary / 交叉链接超限 / 导航塞命题 / 状态越界 / 双归属 / 第一屏泄露 / ID 哈希不符」8 类错误，断言对应规则变红——证明校验器不是摆设。
- **幂等性**：连跑两次 build，产物（忽略 `generatedAt` 时间戳）逐字节一致，是哈希稳定性的最高层验证。
- **规则 10（JSON Schema）**：只在装了 `jsonschema` 时才真正校验，未装则正确 `skipTest`，不误报。

## 二、UI 原型测试（`ui/mock/tests/`）

用无头 Chrome（本机已有）+ Node 22 原生脚本，**不装 npm 依赖**。

### 运行

```bash
cd zhijing
node ui/mock/tests/run_tests.mjs
```

退出码：0 全过 / 1 有失败 / 2 运行出错。结果写 `ui/mock/tests/results.json`。

### 原理

1. `run_tests.mjs` 读 `index.html` + `assertions.js`，拼成**临时测试页**（永远与原型 DOM 一致，不会漂移），并连同 `mock.js`/`mock.css` 复制到临时目录。
2. 无头 Chrome `--dump-dom` 加载测试页（普通模式 + `?bare=1` 各一次）。
3. 断言脚本在页面内跑完，把结果 JSON 写进 `<script id="zj-test-result" type="application/json">`（script 内容不被执行也不被转义，dump-dom 原样输出）。
4. `run_tests.mjs` 解析 JSON，汇总 PASS/FAIL。

### 断言清单（26 条，覆盖全部交互点）

| # | 交互点 | 验证 |
|---|---|---|
| 1 | 初始态 | 首页激活、home tab 高亮 |
| 2 | 切主页面 | garden tab → 庭院激活 + tab 高亮 |
| 3 | 推入二级页 | 卡片 → 详情激活，detail 不抢 tab |
| 4 | 返回栈 | 详情→对照→back×2 回首页；Esc 等价返回 |
| 5 | 主题切换 | html[data-theme] 深浅切换 |
| 6 | 字号缩放 | #phone --scale 跟随 |
| 7 | 问答状态 | 空态/回答中互斥 + 提问文案切换 |
| 8 | 开关 | aria-checked + .is-on 翻转 |
| 9 | 反馈按钮 | 选中变绿 + 兄弟清除 |
| 10 | 四态角标 | mastered/confused 存在、庭院 node--focus 存在 |
| 11 | 深色冠层 | .canopy opacity=0.8 提亮 |
| 12 | 出图模式 | ?bare=1 → body.bare |

## 三、测试本身有效性的反向验证（已做过）

- **kg**：删掉语料中一条 `boundary:` 行 → build 抛 `KgBlockError`，`test_pipeline` 5 条 FAILED；还原后恢复 OK。
- **UI**：把第 2 条断言期待值改成错的 → 输出 `25/26 通过`，第 2 条 FAIL，退出码 1；还原后恢复 26/26。

两条都证明**测试真的会拦截错误，不是恒真摆设**。

## 四、答辩话术

> 我们的知识图谱不是「嘴上说对」，是**跑过的**：43 个 Python 单测 + 26 条前端 DOM 断言全部通过；校验器的 10 条规则做过反向注入（人为塞 8 类错误全被拦下），端到端链路连跑两次逐字节一致。UI 原型的切页/返回栈/深浅色/字号/问答状态/四态角标都有自动化覆盖，双击原型 + 一条命令即可复现。

## 五、边界与后续

- **不测** Android 端 Compose 落地（`ui/tokens/*.kt` 需 Android SDK，属实现队友职责）。
- **不做**像素级视觉回归（一期）；`ui/mock/shots/` 的 10 张基线图留作人工比对，后续可加像素 diff。
- 加新断言：改 `assertions.js`（UI）或对应 `test_*.py`（kg）即可。
