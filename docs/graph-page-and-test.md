# 图谱页面与生成对比测试

> 对应代码：`app/src/main/java/com/example/zhijing/kg/ui/`、`RuleBasedExtractor.kt`、`GraphComparisonRunner.kt`
> 前置：[候选确认](pending-claims.md) —— 本文补上「图谱页面」与「生成质量测试」两块

## 一、图谱页面

### 结构（手机端）

```
顶栏：认知庭院 · 四态计数 · 返回
大纲：横向 chips（「全部」+ 一级章节，各带状态点）
卡片流：单列，默认显示 4 项
下钻：Dialog 覆盖层（不是第四个页面）
```

### 三个不能违反的原则

| 原则 | 落地 |
|---|---|
| 大纲只组织不判断 | 点 chip 是**筛选**；只有卡片右下角能下钻 |
| 角标由卡内命题状态聚合派生 | `GraphCard.badgeStatus`，优先级 易混淆 > 未探测 > 已验证 > 已掌握 |
| 深度不是并列入口 | 没有任何进判断面板的全局按钮 |

### 卡片的信息密度

默认只显示 **4 项**：标题+角标、摘要、交叉链接、下钻按钮。

- 正文折叠成「展开全文」
- 易错注记**只在真有易错时**出现（让卡片「变厚」的那一条）
- 左侧「叶脉书签」竖条 = 状态色

理由：广度图谱第一目标是**可读**，八项信息堆满的卡片不可读。

### 深度面板

**第一屏只有三样**：一句话命题、两个按钮、一句「先自己判断」。

作答后展开揭示屏：判定条 → 为什么 → 成立条件 → **错点落在哪条依赖上** → 原文依据。

错点归因是最有价值的一屏：它告诉用户**错的是哪一类依赖**（形状/值域/统计量/梯度/语义），
而不是「你错了」。

### 状态汇总不做进度条

顶栏只显示四态计数（易混淆 N · 未探测 M）。`confidence` 做成进度条会让用户误以为「刷满就掌握」。

## 二、主题令牌接入

**这一轮顺手把 `ui/tokens/` 接进了 app**，因为这是图谱页面视觉的前提。

| 动作 | 说明 |
|---|---|
| `Color.kt` / `Type.kt` / `Dimens.kt` 复制进 `app/.../ui/theme/` | 替换原来的 Material 紫色模板 |
| `Theme.kt` 重写 | 使用纸墨色板 + `LocalStatusColors` |
| **关闭动态取色** | 四态色是按纸白底调的，动态取色会与它打架 |

`StatusColors` 与 `LocalStatusColors` 改为 public，供 `kg/ui` 消费。

## 三、本地规则抽取

`RuleBasedExtractor` 是 `kg/src/extract_rules.py` 判断题表路径的 Kotlin 移植。

**为什么端上也要一份**：Android 跑不了 Python，而图谱测试需要**就地切换**两条生成路径做对比。

保持三条一致：
1. 表头识别关键字（`判断句/说法/命题` + `是否成立/成立吗/对错`）逐字相同；
2. `truthOf` 的判定前缀（`不成立/错/否` vs `成立/对/是`）逐字相同；
3. 命题 ID 用 `ClaimIds.claimId`，与 Python 的 `claim_id` 同源。

**规则路径的固有边界**：只认 `| 判断句 | 是否成立 | 边界 |` 这类显式表格，
自由文本**不猜**。这正是它与云端抽取的分工，不是缺陷。

## 四、生成对比测试

`GraphComparisonRunner` 同时跑两条路径，并列呈现指标：

| 指标 | 含义 |
|---|---|
| 命题数 | 抽了多少条 |
| 可用 | 满足「有断言、有条件」的条数（可用率） |
| 带证据 | `evidence` 非空，可溯源 |
| 带错点 | 有 `errorKinds`，撞错能定位 |
| 带边 | 有依赖关系 |
| 耗时 | 毫秒 |

**刻意不自动判定哪条路径更好。** 判断优劣需要人工标注（哪条命题是真命题、边界准不准），
程序只给客观指标。把评判权留给人，是这套测试的价值所在。

### 一个容易误判的边界

**云端未配置不是失败，是「未执行」。** 用户没配云服务是合法状态，
不该在报告里显示成一次错误 —— UI 与数据结构都区分了 `success=false` 与 `failure="未配置云端大模型"`。

## 五、测试

```bash
./gradlew :app:testDebugUnitTest --tests "com.example.zhijing.kg.*"
```

新增 15 个用例：

- `RuleBasedExtractorTest`（9）：判断题表识别、边界列提取、无法判定行跳过、自由文本不产出、
  无真值列表格不算、`truthOf` 与 Python 一致、领域词与别名识别、空文本
- `GraphComparisonRunnerTest`（6）：未配置云端标记未执行、配置不完整不发请求、
  规则路径可用率、自由文本下规则为空但领域词可见、重合度、摘要行

全仓 `:app` + `:data` 共 **221 个用例通过**，`:app:assembleDebug` 构建成功。
