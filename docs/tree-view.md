# 结构图：语义布局的节点连线视图

> 对应代码：`app/src/main/java/com/example/zhijing/kg/ui/{TreeLayout,GraphTreeView}.kt`
> 规模目标：24 个大纲节点 / 22 张卡片（当前基线）

## 一、技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| **卡片流 / 大纲** | Compose 声明式（`Card` / `LazyColumn`） | 卡片是**内容**，需要折叠、无障碍、字号缩放 |
| **结构图** | Compose `Canvas` + `detectTransformGestures` | 24 节点 + 上百条线，Canvas 一次绘制、一次整体变换 |
| **不选** | WebView 嵌套 `kg/web` | 交互割裂、性能损耗 |
| **不选** | 第三方图库 | 定制化差、维护风险，需求不匹配 |
| **不选** | 力导向布局 | 见下文 |

## 二、为什么不用力导向布局

力导向每次算出的位置都不同 —— 用户上次记住的「第 3 列是训练」这次就变了，**位置感归零**。

`TreeLayout` 用**语义布局**：一级章节一列，列内按大纲顺序纵向排。位置绑定到结构上，
因此稳定、可记忆、可描述。

三条性质由 `TreeLayoutTest` 守着：

1. 位置确定（同输入同坐标）
2. 一级章节一列，横向递增
3. 列内节点不重叠

## 三、视觉规则

| 元素 | 样式 | 对应设计文档 |
|---|---|---|
| 章节标题 | 主色胶囊 + 浅底 | 「绿色胶囊 = 大纲节点」 |
| 卡片 | 白底圆角矩形，可下钻者描边加深 | 白底圆角矩形 = 卡片 |
| 层级连线 | **实线** | 实线 = 大纲层级 |
| 交叉链接 | **虚线** | 虚线 = 横向跳转的唯一视觉线索 |
| 右上角圆标 | 主色圆 + 命题数 | 「小圆标是命题数」 |

## 四、交互

| 手势 | 行为 |
|---|---|
| 双指缩放 | 0.35–2.4×，以手势中心为锚点补偿偏移 |
| 单指拖动 | 平移 |
| 点卡片 | 有命题的卡 → 下钻判断面板 |
| 右上角 | ＋ / － / 复位 |

**结构图与卡片流是同一页面的两种呈现**（顶栏切换"结构图 / 卡片流"），
不是两个一级 tab —— 结构图与广度视图功能重叠，并列会让导航变乱。

## 五、两种视图共用同一个判断面板

`DescendDialog` 被提成独立组件：卡片流和结构图都能下钻，但
**深度面板只有一份实现**，避免两种视图各写一遍。

## 六、修掉的两个真 Bug

### 6.1 `associateBy` 覆盖同 path 的卡片

```kotlin
// 错：一个章节下多张卡时，只保留最后一张
val byPath = graph.cards.associateBy { it.outlinePath }
```

表现为「结构图上少了卡片」。改为 `groupBy` 后全部保留。

### 6.2 `drawText` 参数名

`drawText(textLayout = ...)` 不编译；正确参数是 `textLayoutResult`。

## 八、规模说明

当前方案针对 24 节点设计，**未做视口裁剪**。

| 规模 | 是否够用 |
|---|---|
| 24 节点（当前） | ✅ |
| 192 节点（对标 cs-math-skill-tree） | ⚠️ 需要按章节分列 + 视口内绘制 |
| 10,000+ | ❌ 必须重做（分区 + 懒加载） |
