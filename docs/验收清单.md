## 三、改动详解（按主题，重点看这一节）

### 3.1 结构图布局与手势

- **层级宽度**：删卡片后 `LEVEL_WIDTH` 仍含 `CARD_WIDTH`，三层树内容总宽 924dp → **584dp**，
  屏幕适配从 0.42 提到 0.67，字实际变大 60%。同时删掉 `CARD_WIDTH` / `CARD_GAP` / `PREREQ_LANE` 三个死常量。
- **平移钳制**：`GraphTransform.clampOffset` 把内容限制在「内容尺寸 + 视口 30%」内，拖 10 次也不会丢。
- **以手指为中心缩放**：`newOffset = centroid - (centroid - oldOffset) * (newScale / oldScale)`，
  centroid 与 offset 统一在 dp 概念值上算，不引入第二套单位。
- **行距**：`ROW_GAP` 22 → 28，弧线在缝隙里绕得开。

文件：`kg/ui/TreeLayout.kt`、`kg/ui/GraphTransform.kt`、`kg/ui/GraphTreeView.kt`

### 3.2 连线体系（用户逐条下的规则，冲突时以用户为准）

| 规则 | 实现 |
|---|---|
| 未选中任何卡时**只画层级线**，实线虚线都不显示 | `EdgePresentation.roleOf(selected == null) → null` |
| 选中后只显示与该卡相连的线 | 同上，按 `fromNode` / `toNode` 过滤 |
| 配色：必须前置 `#D63031` 实线+箭头、推荐前置 `#F39C12` 虚线无箭头、后续 `#0984E3` 实线+箭头 | `GraphLineColors` + `Role` 分发 |
| 相邻同列**不用直线**，走二次贝塞尔、线在卡片下面 | `Line.Route.CURVE` + `curveControl`（相邻鼓 10dp，跨列推荐 14dp） |
| 必须前置若能沿层级线到达，**沿用层级折线**，不重复画斜线 | 跨列必须 → `Route.ELBOW` |
| 新增「后续线」 | 选中卡的出边 → `Role.SUCCESSOR` |
| **长跳依赖走列外车道** | 同列且节点顶部相距 > 1.5 行 → `Route.LANE`；车道 = 该列最右 +10dp，同列多条依次外推 8dp（3 条一循环），内容宽度多留 40dp |
| **车道箭头指在节点右边缘** | LANE 两端取侧边中点（源右中 → 车道 → 目标右中），不再沿上边缘横穿进卡片中心 |
| **三种依赖线粗细统一 3dp** | `DEPENDENCY_LINE_WIDTH = 3f`；层级线 1.6dp、交叉虚线 1dp 保持不变 |
| **跨章节依赖淡化** | 透明度 0.5（不再改线宽，避免「更细 = 另一类关系」的误读），图例注明「跨章节已淡化」 |

文件：`kg/ui/EdgePresentation.kt`、`kg/ui/TreeLayout.kt`（`Node.chapterPath` / `Line.crossChapter`）、`kg/ui/GraphTreeView.kt`

### 3.3 卡片三态（技能树方案的 P0）

- `SkillProgress` 纯派生，**不建表**：`LIT / READY / LOCKED` + 「到终点还有几张卡」。
- 点亮规则（修过两次，都是实测踩出来的）：
  1. 最初按「卡内 ≥80% 命题 **MASTERED**」，但一轮下钻每条只判一次只到 `VERIFIED` →
     除 1.1 外全图卡死。改为按**已练**比例。
  2. 「练过」的两种合法形态：判对过该命题的判断题，**或**该命题下有干预点被拨对。
     出厂卡片有「预测→揭示」，用户常常只拨条件不做判断题，只认命题状态会永远点不亮。
  3. 有 `CONFUSED` 且**未练过**才阻断；已经拨对过条件的不再挡（否则一条陈旧状态能永久卡住）。
- 界面：节点三态描边 + `✓/＋/□` 图标（颜色在缩放后不可靠，图标做第二重编码）+ 锁定虚线框；
  顶栏 `可学 N` / `已完成 x/y` 两个 chip + 「现在能学」面板。
- 节点详情每张卡一行状态：`已点亮 · 2/2 条已练` /
  `未解锁 · 1/3 条已练，还差 2 条前置，1 条易错待纠正：「断言…」`，
  并在易错时给「清空这张卡的记录」出口。

文件：`kg/SkillProgress.kt`、`kg/ui/GraphScreen.kt`（`cardStateLine` / `NodeDetailSheet`）

### 3.4 点亮动效

- `SkillAnimation` 判定「刚点亮」：首次进入不算、新出现节点不闪、只认 `非 LIT → LIT`。
- `GraphTreeView` 用 `LaunchedEffect` + `animate` 推进 0..1 进度，**320ms、最多 6 个并发**，
  绘制期只读进度画外扩描边，**不在 DrawScope 写状态**（项目踩过无限重组卡死）。

文件：`kg/ui/SkillAnimation.kt`、`kg/ui/GraphTreeView.kt`

### 3.5 深度交互

- 预测 → 揭示状态机：出题顺序固定、不能跳过、判定只走本地 `ContractEvaluator`，模型不判对错。
- **重新下钻跳过已拨过的干预点**：条件题会话只在内存里，退出即丢；不跳过的话，一张 5 个干预点的卡
  每次进来都要先重答 5 道才能看到判断题，用户会以为「答了没反应」。
- **理解路径可重走**：`ConditionProbeSession.forCard(..., startAt)`；只放开 `!matched` 的步骤
  （已改对的重走会覆盖「原来猜 X」这条证据）；重走时把目标从跳过集合里剔除，否则会话直接 Done。
- **路径一句话摘要**：`你从「首步 previousPredicted ?: predicted」走到「末步 predicted」`，
  首末相同或路径为空返回 `null` 不渲染。

文件：`kg/depth/ConditionProbeSession.kt`、`kg/ui/GraphScreen.kt`（`DescendDialog`）、`kg/ui/PathSummary.kt`

### 3.6 前置可解释（roadmap §2.3）

- `PrerequisiteLink.reason` / `source` 一直随 assets 与 `kg_generated_prerequisite.why` 解析下来，**此前从未渲染**。
- 现在节点详情每张卡最多列 3 条：`必须前置：<标题> —— <为什么>（人工书写|未经核实）`，
  超出折叠为「还有 N 条前置」。
- 标题缺失（卡片被删）回退成 `crd.` 之后的尾段，不留空白。

文件：`kg/ui/PrerequisiteText.kt`、`kg/ui/GraphScreen.kt`

### 3.7 数据层：迁移与生成图谱命题

- **真实迁移**（此前靠 `fallbackToDestructiveMigration()` 清库）：
  - v6 → v7：建 `kg_condition_probe`；
  - v7 → v8：建 `kg_generated_claim`；
  - 打开 `exportSchema`，schema 导出到 `data/schemas/`；`ZhijingMigrationTest` 用导出的 `createSql`
    重建 v6/v7 旧库再升级，**不手抄 DDL**，也不挂 fallback（迁移写错就红）。
- **生成图谱的命题**（v8 新表 `kg_generated_claim`，主键 `topic_id + claim_id`，带 `card_id`）：
  - 为什么不复用 `kg_runtime_claim`：那张表是「云端给知识库新增命题」，要求 `pending → confirmed` 才进图；
    生成命题是那份图谱的一部分，主题删掉就该一起消失。
  - 生产：`GraphGenerator` 出图后按卡调 `CloudClaimExtractor`（**前 12 张卡**、正文 20–900 字），

  - 合并：`GraphAssembler` 按 `cardId` 挂到 `GraphCard.claims`（`CLOUD` / `verified = false`），
    判题面板标「未经核实」。
  - 删除：`replaceGraph` / `deleteWholeGraph` 在同一事务里删建命题，不留孤儿。

文件：`data/.../ZhijingDatabase.kt`、`data/.../entity/KgGeneratedClaimEntity.kt`、`kg/GraphGenerator.kt`、`kg/GeneratedClaimBuilder.kt`

### 3.8 生成图谱「答完不点亮」的两个根因（值得记住）

1. `GraphAssembler.load()` 只按「出厂 + 云端增量」命题 id 查状态，**生成命题不在其中** →
   永远返回默认 `UNPROBED`。改为把 `kg_generated_claim` 的 id 一并查。
2. 「练过」只认判断题状态 → 只拨条件的卡片永远不亮。见 §3.3 第 2 条。

> 出厂图谱是硬编码 assets，生成图谱走 Room，两者**只有 `GraphAssembler` 合并那一步共用**。
> 排查问题时不要用出厂图谱的表现反推生成图谱。

### 3.9 内容与数据管线

- 增补源 `kg/data/source/deep_supplement.json` 支持三类，由 `kg/src/export.py` 的 `merge_supplement()`
  合并进 assets：
  1. `prerequisites`（21 条卡片级前置）；
  2. `triples`（12 条 / 48 个干预点）；
  3. `edges`（22 条补边，按 `id` 去重、端点必须是真实命题、自环丢弃并计数）。
- 现状：36 条命题 **每一条都有深度边**（38 条 = 16 条 build 产出 + 22 条增补），
  揭示屏因此能显示「成立边界与反例」（按 `from == claimId` 反查，不依赖 build 的 `edgeIds`）。
- **为什么必须走增补源**：直接手改 `assets/kg/graph.json`，跑一次 `export`（包括 kg 的导出用例）
  就被整份覆盖，「预测 → 揭示」会静默变空 —— 这是踩过的数据事故。

## 四、没做的（按重要性）

### 4.1 模型生成契约流水线（roadmap §3.3 P4）—— 唯一的大缺口

- 现状：`kg/prompts/extract_triples.md` 是完整提示词（条件/机制/反事实、5 个契约算子、准入标准），
  但**全仓没有任何代码引用**；三元组全部由人工写进增补源。
- 缺口：没有「模型产契约 → `ContractEvaluator.validate()` 自动拒不自洽 → 人工抽查 → 入库」这条链路，
  所以内容规模化仍然靠人。
- 现成条件：落点 `kg/data/source/deep_supplement.json` 的 `triples` 已就绪；闸门已有
  （`BundledTriplesTest` + `Triple.isValid` + `ContractEvaluator.validate()`）。
- 预估 2 天+；先要回答「生成图谱要不要接」——见 4.2。

### 4.2 生成图谱没有三元组

- 生成图谱有命题（可下钻做判断题），但 `triples` 恒空 → **「预测 → 揭示」对生成图谱不可用**。
- 原因：契约只能表达维度与轴对齐，模型生成的正文没有可形式化的维度声明；
  强行产出只会得到一堆「预置答案」，质量不可控。
- 若要做，建议链路：生成时按卡让模型同时输出 `triples`，过 `Triple.isValid` 与误判库闸门，
  落 `kg_generated_triple`（需要 v9 迁移）。

### 4.3 契约引擎的覆盖边界（不是 bug，是设计边界）

| 条件类型 | 能否本地判定 | 说明 |
|---|---|---|
| `shape` | ✅ | 维度/内维/转置，`MatMul` / `ElementWise` |
| `statistics` | ⚠️ 部分 | 只有 `SoftmaxSum`（轴对齐求和为 1）；方差类（缩放、BN）只能预置答案 |
| `range` | ⚠️ 部分 | 只能判结构层面，值域语义仍需人工 |
| `gradient` | ❌ | 需要符号求值/反向传播，成本 3 倍，roadmap 明确先不做 |
| `semantic` | ❌ | 无法形式化，只能人工写干预 + 后果 |

第二批 6 条三元组（交叉熵 logits、BN 小 batch、ReLU 接 Softmax、注意力缩放、掩码顺序、多头共享输入）
全部标 `computable = false` + `AUTHORED_HUMAN`，原因就在这里：**写不出诚实契约就不硬编**。

### 4.4 其他

- 理解路径分支树 / ASK 追问节点：roadmap 自己写明第一版不做，交互复杂度高。
- 命题质量回归集：没有 golden set，模型产出目前靠人工抽检。
- 生成命题只覆盖**前 12 张卡**（每卡一次模型调用，50 张要等太久），其余卡片保持「暂无习题」。

## 六、接手须知（坑与约定）

1. **不要手改 `app/src/main/assets/kg/graph.json`**：跑一次 `export` 就被覆盖。改内容改
   `kg/data/source/deep_supplement.json`（前置 / 三元组 / 边），再 `python kg/src/export.py --all`。
2. **加表就必须补迁移**：`version + 1` + `Migration(n, n+1)`（DDL 抄自生成的
   `data/schemas/.../{n+1}.json`）+ `ZhijingMigrationTest` 加一条用例。
   目前 `fallbackToDestructiveMigration()` 只兜底 v6 以前。
3. **不要在 DrawScope 里写 Compose 状态**：会无限重组卡死。动画进度在 `LaunchedEffect` 推进，绘制期只读。
4. **坐标单位**：布局产出 dp 概念值，绘制乘 density；
   `pxPerDp = fitScale * scale * density.density`，不要引入第二套。
5. **依赖线「未选中不显示」是用户定的规则**，不要改回全量显示；淡化只降透明度，不改线宽。
6. **判定唯一裁判是 `ContractEvaluator`**，模型不判对错；干预是有限预设，不是自由输入。
7. **生成图谱与出厂图谱不要互相类比**：一个走 Room，一个是硬编码 assets，状态查询路径不同。
8. 提交前跑齐 5.1 的四条命令；`:app` / `:data` 用例数变化要同步到 `CODEBUDDY.md`。

## 九、何时启动暂缓项（触发条件）

不是按日历排期，而是按数据信号。

| 项 | 触发条件（任一） | 当前值（2026-11-18） | 触发后动作 |
