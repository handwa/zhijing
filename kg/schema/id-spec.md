# 节点与边的 ID 规范（id-spec）

> 设计文档《广度知识图谱与深度探索图谱》核心约束第 1 条：**命题 ID 是唯一主键（单一真相源）**。
> 本规范把这句话落成可执行的规则，`kg/src/kg_model.py` 里的 `claim_id / card_id / edge_id / is_valid_id` 是唯一实现，`validate_graph.py` 会逐条校验。

## 1. 格式

```
<前缀>.<语义路径>.<稳定短哈希>
```

- **前缀**：五选一，决定节点种类，不允许自造。
- **语义路径**：小写 ASCII + 数字 + `.` `_` `-`，`.`
- **稳定短哈希**：只对 `clm` / `ent` / `edg` 三类强制要求，取 `sha1(规范化文本)` 的前 4–8 位小写十六进制。

| 节点 | 前缀 | 格式 | 示例 |
|---|---|---|---|
| 分类节点 outline | `out` | `out.<语义路径>` | `out.arch.ffn.linear` |
| 卡片 card | `crd` | `crd.<语义路径>[.<序号>]` | `crd.arch.ffn.linear` |
| 命题 claim | `clm` | `clm.<语义路径>.<hash4>` | `clm.arch.ffn.linear-in-dim.3c9a` |
| 实体 entity | `ent` | `ent.<kind>.<slug>.<hash4>` | `ent.method.relu.5f21` |
| 边 edge | `edg` | `edg.<类型短码>.<hash6>` | `edg.dep.7f3a1c` |

类型短码：`dep` 依赖 / `aff` 影响 / `con` 组成 / `ctr` 对比 / `ref` 反例 / `pre` 前置。

## 2. 哈希怎么算

```
hash = sha1(normalize(文本))[:N]
normalize = 去首尾空白 → 去所有空白 → 去标点（，。！？；：、（）「」"" 等） → 转小写
```

因此：

- 只改标点、改空格 → **ID 不变**（排版微调不会炸掉交叉链接）；
- 改了实词（哪怕一个字）→ **ID 变化**（这是有意的：命题已经不是同一条命题了）。

边的哈希取 `sha1(from|to|type)`，端点或关系类型一变就换 ID，不会出现「旧边指向新语义」。

## 3. 稳定性要求（把它当发布物）

1. **ID 一旦发布不得改名。** 改名等价于删除旧节点 + 新建节点，所有交叉链接、下钻入口、状态回写全部失效。
2. **命题正文是 ID 的来源**，修订命题时先判断：是「换个说法」还是「换了个断言」。前者应保留原 ID 并更新 `statement`，后者必须换 ID 并在 `meta.warnings` 留迁移记录。
3. **分类节点不参与命题身份。** 大纲树是阅读结构，命题图是判断结构，两者只在「叶子卡片 ↔ 命题」处对接；因此 `out.` 允许按目录调整而无需哈希。
4. **一幅图谱内 ID 全局唯一**，跨类型也不重复（靠前缀天然隔离）。

## 4. 反例（会被校验器拦下）

| 写法 | 问题 |
|---|---|
| `claim-001` | 无前缀、无哈希、纯流水号，改名即断链 |
| `clm.arch.linear` | 缺 hash4，命题无法稳定寻址 |
| `clm.Arch.Linear.3C9A` | 含大写，正则不放行 |
| `clm.arch.linear.3c9a.extra` | 路径段允许多级，但末尾必须是 4–8 位哈希 |
| `out.arch.linear` 用来挂命题 | 分类节点不可下钻，命题必须挂 `crd.` 叶子卡 |

## 5. 与数据库的映射（导入时）

`export.py --target sql` 生成的 `kg_node` / `kg_edge` 表直接把 `id` 当主键 TEXT 用，不做自增整数映射 —— 一旦引入整数主键，ID 就不再是唯一真相源，图谱与业务表之间要多维护一张映射表，违背「单一真相源」。

## 6. 变更流程

```
改语料 → build_graph.py 重建 → validate_graph.py 通过 → diff 出 ID 变化清单 → 人工确认
```

`build_graph.py` 会在 `meta.warnings` 里输出「新增 ID / 消失 ID」清单，用于判断是否属于非预期改名。
