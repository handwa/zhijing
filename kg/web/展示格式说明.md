# 展示格式说明（web 演示 → Android 落地）

> 这份文档定义「长什么样」和「为什么这么长」，`index.html` 是它的可运行参照。
> Android 端做 M6-01 认知庭院时，按这里的结构与规则翻译成 Compose 即可，不要另起一套视觉语言。

## 1. 三个屏，三种动作

| 屏 | 用户动作 | 核心问题 | 成功标准 |
|---|---|---|---|
| 广度视图 | 读、查、定位 | 这个主题**由哪些部分**组成 | 读完能说出全貌 |
| 结构图 | 看关系、找位置 | 这些部分**怎么连** | 知道哪里还有没碰过的块 |
| 深度面板 | 判、撞错、看边界 | 这个点**到底成立吗** | 能独立判断并知道错在哪 |

深度面板**不是第四个 tab**，只能从叶子卡片的下钻按钮进入；没有独立入口、没有独立 URL —— 这是设计文档的硬约束，也是它和「加了测试的思维导图」的分界线。

## 2. 广度视图

```
┌ 顶栏：标题 · 规模芯片 · 视图切换 · 重置状态 ────────────────┐
├ 252px 大纲树 ─┬ 卡片流 ────────────────────────────────┤
│ 1 前馈网络     │ ┌ 卡片 ─────────────────────────────┐ │
│   1.1 Linear   │ │ 标题            [易混淆]           │ │
│     正文内容 2 │ │ 面包屑（大纲标题链）                 │ │
│   1.2 ReLU     │ │ 摘要（一句话）                       │ │
│ 图例：四态     │ │ 正文（超过 260 字折叠 + 遮罩）        │ │
│                │ │ 交叉链接 ≤5 条（按权重降序）          │ │
│                │ │                    [下钻 N 条命题]   │ │
└────────────────┴────────────────────────────────────┘
```

规则：

1. **大纲节点只组织不判断**：点击是筛选，不是下钻；只有卡片右下角能下钻。
2. **卡片角标四态**：未探测（灰）/ 已验证（蓝）/ 已掌握（绿）/ 易混淆（橙）。角标由该卡下的命题状态**聚合派生**，不单独存储。
3. **交叉链接封顶 5 条**：按 `weight` 降序，chip 上只显示目标卡标题，悬停显示「共享实体 + 权重」。超过 5 条就不是阅读容器，而是节点图了。
4. **易错点注记**：卡片下方橙线小条，来自深度侧撞错时记下的 `misconceptions[0]`。这是「让卡片变厚」的那一条信息。
5. **摘要与正文首段重复时不重复显示**：摘要本来就是首句，重复一遍是噪音。

## 3. 结构图

- 布局：**一级章节一列**，章节内的节与卡片纵向排列。刻意不用「所有叶子排成一行」——27 张卡横排 5000px，缩到 0.3 倍谁也读不了。
- 节点：绿色胶囊 = 大纲节点（层级），白色圆角矩形 = 卡片；卡片上角的小圆标是命题数。
- 连线：实线 = 大纲层级；**虚线 = 交叉链接**（线宽随权重），虚线是「横向跳转」的唯一视觉线索。
- 交互：滚轮缩放（0.35–2.4×）、拖动平移、点击卡片跳到广度视图对应位置、右上角 −/+/复位。
- 性能：纯 SVG，27 节点 / 40 余条线，不需要 canvas。

Android 落地建议：`Canvas` + `detectTransformGestures`，节点数上百时改用分层抽样或按章节懒加载，不要一次性铺全图。

## 4. 深度面板

### 4.1 第一屏（唯一允许出现的内容）

```
s2-5 · 2.5 语义依赖                                    ✕
这个说法成立吗？
只要形状能对上，接什么层在语义上都是正确的。
先自己判断，条件与边界在作答之后才展开。
[ 成立 ]                     [ 不成立 ]
第 1 / 2 条命题 · 易混淆
```

三件事必须同时成立：

1. 只有**一句话命题**；
2. 只有**两个按钮**；
3. **不出现任何条件、反例、解释**。

这不是风格问题，是产品原则：用户没有参照物，多给一个信息他就不知道该干什么。反向约束了数据模型——`reveal` 必须与 `breadth` 分开存。

### 4.2 揭示屏

| 区块 | 内容 | 作用 |
|---|---|---|
| 判定条 | ✓ 判断正确 / ✗ 撞错了 + 正确结论 | 先给结论，不铺垫 |
| 为什么 | `reveal.explanation`（默认由「结论 + 原文依据」拼） | 说清依据 |
| 成立条件与边界 | `claim.conditions[]` | 划出适用范围 |
| 错点落在哪条依赖上 | `reveal.errorKinds[]`，标签为「形状/值域/统计量/梯度/语义依赖」 | **最有价值的一屏**：告诉他错的是哪一类，而不是「你错了」 |
| 关联的带条件边 | 对端命题 + 前提 / 边界 / 反例 + 权重 | 把「依赖与影响」摊开 |
| 这条误解会被记下来 | `misconceptions` | 让回写可见，用户知道代价 |
| 动作 | 下一条命题 / 回到卡片 | 保持节奏 |

### 4.3 键盘

`1` / `←` = 成立，`2` / `→` = 不成立，`Esc` 关闭。移动端不依赖键盘，按钮本身足够大（48px 高）。

## 5. 状态回写与派生

| 事件 | 深度侧状态 | 广度侧表现（派生） |
|---|---|---|
| 从未作答 | `unprobed` | 灰点「未探测」 |
| 判对 1 次 | `verified` | 蓝点「已验证」 |
| 连续判对 2 次 | `mastered` | 绿点「已掌握」 |
| 判错 | `confused` | 橙点「易混淆」+ 易错点注记 |

- **只回写 4 个字段**：`probe_status`、`last_probed_at`、`misconceptions[]`、`confidence`。
- `attempts` / `correct` 只留在深度侧，用于算状态，不出现在广度视图。
- 「撞错后纠正」与「仍易错」必须区分：判错 → `confused`；之后连续判对两次才会变 `mastered`，一次正确只到 `verified`。
- 广度侧**不存状态**：演示页把状态放在 `localStorage`，渲染时聚合；Android 端应直接查 `kg_node.probe_status` 聚合，不要往 `topic_table` 里抄一份。

## 6. 视觉规范

| 项 | 值 |
|---|---|
| 主色 | `#2f6f4f`（植物绿，呼应「认知庭院」） |
| 背景 / 面板 | `#f6f8f6` / `#ffffff`（深色模式 `#10141a` / `#171d24`） |
| 正文色 | `#1b2420`，次要 `#3d4a44`，弱化 `#6f7d76` |
| 字号 | 正文 15，卡片标题 15.5，命题 21，面板标题 11.5（全大写式小标题） |
| 圆角 | 卡片 14，按钮胶囊 999，面板 18 |
| 阴影 | 卡片 `0 1px 2px + 0 8px 24px`，面板 `0 24px 64px` |
| 动效 | 出现 220ms 上浮 + 淡入；判定条不弹窗、不震动 |

深浅色跟随系统（`prefers-color-scheme`），状态色两套都单独调过对比度，不要直接复用。

## 7. 四个反模式（做的时候会自然滑向）

1. **把节点图画成主界面**：广度侧一上来就是一堆点和线，用户不知道从哪读。大纲 + 卡片才是阅读容器。
2. **把条件铺在第一屏**：条件一可见，判断就退化成「对照答案」，撞错价值归零。
3. **把状态做成进度条**：`confidence` 不做进度条，容易让用户误以为「刷满就掌握」。
4. **给深度图谱加全局入口**：一旦有独立入口，它就和广度并列了，叶子卡片的主归属失去意义。

## 8. 验收清单

- [ ] 双击 `index.html` 能打开，无控制台报错（`file://` 下不依赖 fetch）
- [ ] 大纲点击可筛选，卡片可按关键词搜索
- [ ] 每张卡交叉链接 ≤5 条且按权重降序
- [ ] 叶子卡片能下钻，首页没有深度入口
- [ ] 第一屏只有命题 + 两个按钮，条件与解释在作答后才出现
- [ ] 判错后能看到「错点落在哪条依赖上」，返回广度视图角标变橙并出现易错点注记
- [ ] 「重置状态」能回到种子状态
- [ ] 结构图可拖动缩放，点击卡片能跳回广度视图
- [ ] 窄屏（<980px）下大纲折叠为上方区块，卡片单列
- [ ] 深色模式下文字对比度正常（可用系统深色模式验证）
