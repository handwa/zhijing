# 实体抽取提示词（端侧 LLM）

> 对应说明书 4.2.2「后台理解」与 3.3.1「分析结果（关键词/实体/情感/主题/立场）」。
> 落点：`ParseTaskType.ANALYZE` 执行时，在关键词/主题之后追加的一次调用。
> 模型：GLM-Edge-1.5B（int4）或 0.5B 档；0.5B 档建议只跑「实体抽取」这一件小事，不要和主题、情感混在一次调用里。

## 1. 为什么要单独一次调用

小参数模型一次做多件事，字段会串味：让它同时抽关键词、实体、主题，最容易出现「实体里混进主题词」。
所以拆成两段：先抽关键词与主题（已有链路），再用本提示词单独抽实体，输出只含实体。

代价是多一次前向，收益是字段干净、可直接落图谱节点。

## 2. system prompt（原样投喂）

```
你是知识抽取器，只输出 JSON，不解释、不寒暄、不使用 Markdown 代码块。
任务：从用户给的中文文本里找出「实体」，按 kind 分类。

kind 只能取以下六种之一：
- concept   概念（如：梯度消失、遮蔽、位置信息）
- method    方法/层/算子（如：ReLU、LayerNorm、缩放点积注意力）
- metric    指标/损失（如：交叉熵、准确率）
- tool      工具/框架（如：PyTorch、llama.cpp）
- dataset   数据集（如：ImageNet）
- formula   公式或张量记号（如：logits、(N, C)、sqrt(d_k)）

规则：
1. name 必须逐字出现在原文里，不许改写、不许翻译、不许补充原文没有的词。
2. 同一个实体的不同写法只保留一个，其余放进 aliases。
3. 按在文中出现的次数从多到少排序，最多 12 个。
4. 泛泛而谈的词（方法、模型、数据、问题）不算实体。
5. 输出必须是单个 JSON 对象，形如：
{"entities":[{"name":"ReLU","kind":"method","aliases":["线性整流"]}]}
6. 没有实体时输出 {"entities":[]}。
```

## 3. user prompt 模板

```
文本：
"""
{content}
"""
```

调用参数建议：

| 参数 | 值 | 理由 |
|---|---|---|
| temperature | 0.1 | 抽取要稳定，不要发挥 |
| max_generate_tokens | 320 | 12 个实体足够，超过说明在啰嗦 |
| top_p | 0.9 | — |
| stop | `}` 之后换行 | 防止模型继续写解释 |

## 4. few-shot（0.5B 档必须带，1.5B 档可省）

```
文本：
"""
ReLU 是逐元素激活，把负半轴压成 0；它不改变张量形状。而 Softmax 沿类别维归一化，
输出求和为 1。两者常被误认为可以随意互换。
"""

输出：
{"entities":[
 {"name":"ReLU","kind":"method","aliases":[]},
 {"name":"Softmax","kind":"method","aliases":[]},
 {"name":"张量形状","kind":"formula","aliases":["形状"]},
 {"name":"类别维","kind":"formula","aliases":[]}
]}
```

注意示例里**没有**把「负半轴」「归一化」抽成实体 —— 它们是描述，不是可索引的专名。这个边界要在示例里体现，否则小模型会把所有名词都塞进来。

## 5. 与规则抽取的分工

`kg/src/extract_rules.py` 用的是**确定性词典 + 加粗 + 行内代码**，好处是零幻觉、可复现；坏处是只认识词表里的词。
两者不是替代关系：

| | 规则抽取 | LLM 抽取 |
|---|---|---|
| 覆盖 | 词表内 | 开放词表 |
| 可复现 | 完全可复现 | 温度 0 也仍有波动 |
| 幻觉 | 无 | 会造原文没有的词 |
| 用途 | 建库、回归测试 | 运行时扩充、离线补全 |

所以线上策略是：**LLM 抽出来的实体，必须逐字回查原文，回查不到就丢弃**（规则 1 的硬校验在代码里做，不靠模型自觉）。

## 6. 解析失败与降级

| 情况 | 处理 |
|---|---|
| 输出不是 JSON | 取第一个 `{` 到最后一个 `}` 重试解析 |
| JSON 合法但 entities 不是数组 | 视为空结果，保留关键词结果，不重试 |
| 实体名的原文回查失败 | 丢弃该条，其余保留 |
| 连续两次失败 | `analysis_status` 仍标 DONE（关键词与主题有效），只把实体置空并记本地日志 |

对应说明书 4.2.2「处理失败的自动重试，还失败的在内容上标出来」与 5.2「输出格式可用率不低于 95%」。
