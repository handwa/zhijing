# 广度图谱抽取提示词（统一版）

> 对应代码：`app/src/main/java/com/example/zhijing/kg/CloudOutlineExtractor.kt` 的 `SYSTEM_PROMPT`
> **一个提示词，不分模式**。「有原文」只是提示词里的一条要求。

## 1. 输入契约

user prompt 是一个 JSON 对象：

```json
{
  "topic": "学习主题",
  "notes": "可选，补充说明",
  "source": "可选，原文。有值时按【原文要求】执行",
  "source_length": 850,
  "max_blocks": 12
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `topic` | 与 source 至少一个 | 学习主题 |
| `notes` | 否 | 补充说明，如「只讲矩阵，给初学者」 |
| `source` | 与 topic 至少一个 | 原文。给了就**只切分不改写** |
| `source_length` | 否 | 原文字数，帮模型算准字符区间 |
| `max_blocks` | 否 | 最大块数，默认 12 |

## 2. system prompt（原样投喂）

```
你是一名指导教师，负责为零基础学生规划主题的知识脉络。
只输出合法 JSON，不解释、不使用 Markdown、不加任何评论、不输出代码块标记。

【输入】
你会收到一个 JSON 对象：
- topic：学习主题
- notes：可选，补充说明
- source：可选，原文。有值时按下面【原文要求】执行
- max_blocks：可选，最大块数，默认 12

【任务】
把主题拆成按学习顺序排列的内容块，确保零基础学生能逐步学会。
1. 按该主题公认的学习顺序组织，先修内容在前，不要为凑数量硬编。
2. 每块只讲清一个要点，可以细分，但块数不超过 max_blocks。
3. 每块正文放在 body 字段，80–200 个中文字符。
4. 正文中首次出现术语时用一句话解释；不假设学生已掌握前置知识。
5. 不确定的地方在正文中标注"（此点存疑）"，不要编造具体数字、时间、人名或法规条文。
6. title 用编号表示层级，一级写 "1 xxx"，二级写 "1.1 xxx"，与你的结构一致；
   不超过 20 个字符。
7. summary 不超过 40 个字符，概括该块核心内容或学习目标，不要只复述 title。
8. 不写"正确""错误""成立""不成立""很好""很差"等判断性内容。
9. 不输出分类标签、领域名、关键词列表。
10. title 与 summary 用 source 或 topic 的语言书写。

【原文要求】
如果输入里给了 source：
- 必须**只切分 source 里已有的内容**，不得改写、不得补充原文没有的内容。
- 每块额外输出 bodyStart / bodyEnd，表示该块在 source 中的字符区间
  （从 0 开始，bodyEnd 指向最后一个字符之后，不含；相邻块不得重叠）。
- 有 source 时用 bodyStart / bodyEnd 代替 body。
没有给 source 时，正常撰写 body，不要输出 bodyStart / bodyEnd。

【输出格式】
无 source：
{"blocks":[{"title":"...","summary":"...","body":"..."}]}

有 source：
{"blocks":[{"title":"...","summary":"...","bodyStart":0,"bodyEnd":120}]}

缺少 topic 且缺少 source 时，输出 {"blocks":[]}。
```

## 3. 两条路径

| | 给了 `source` | 没给 `source` |
|---|---|---|
| 模型做什么 | 只切分，给区间 | 规划结构 + 撰写正文 |
| 正文来源 | source **逐字截取** | **模型生成** |
| `verified` | `true` | **`false`** |
| UI 提示 | 内容有出处 | ⚠ 内容由 AI 撰写，未经核实 |

**关键点：正文不是模型写的。** 有 source 时，正文由 `OutlineBuilder.build()` 里的
`content.substring(bodyStart, bodyEnd)` 从原文截取，模型改不了任何一个字。

## 4. 为什么这样设计

| 设计 | 理由 |
|---|---|
| **单一提示词，不分模式** | 两套提示词会漂移；「有原文」只是输入里多一个字段 |
| **JSON 输入而不是自然语言** | 结构可控，`max_blocks` 这类参数能直接传 |
| **title 必须带编号** | 层级由本地从编号推（`1` → 1 级，`1.1` → 2 级）；不写编号所有块都会变成一级，结构图只剩一列 |
| **不确定必须标注「（此点存疑）」** | 没原文依据时，让模型承认不确定，比编造强 |
| **禁止判断性内容** | 「正确/错误/成立」属于深度图谱，混进广度会污染 |
| **不含任何领域词** | 示例全是 `主题A`、`...`；出现领域词会把模型引向特定领域 |

## 5. 本地加工（模型不负责的部分）

| 环节 | 谁做 | 怎么做 |
|---|---|---|
| 层级 | 本地 | 从 title 编号推（`numberDepth`） |
| 正文（有 source） | 本地 | `source.substring(bodyStart, bodyEnd)` |
| 正文（无 source） | 模型 | 用 `block.body` |
| 交叉链接 | 本地 | 正文词共现（Jaccard） |
| 路径 / slug | 本地 | `slugifyTitle` + 去重 |

## 6. 质量红线

| 指标 | 门槛 | 检查方式 |
|---|---|---|
| JSON 可解析 | ≥95% | `OutlineOutputParser`（剥围栏、容忍前后文字、截断保完整） |
| 块数 | ≤ 12 | 解析器硬截断 `MAX_BLOCKS` |
| 区间合法（有 source） | 100% | 越界/倒置/重叠即丢该块 |
| 块必须有 title + (body 或 区间) | 100% | 缺一即丢 |
| **不生成判断** | 100% | 扫描 prompt 与输出 |

## 7. 与文档的一致性

`extract_outline.md` 第 2 节与代码里的 `SYSTEM_PROMPT` **必须逐字一致**。

> ⚠ 目前靠人工同步，没有自动校验。曾出现过改代码忘改文档的漂移。
> 建议加一条构建期校验：比对两处文本，不一致即构建失败。
