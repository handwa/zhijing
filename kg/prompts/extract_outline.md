# 广度知识图谱抽取提示词（通用）

> 对应设计文档「广度知识图谱」：回答「这个主题由哪些部分组成」，目标是**覆盖**。
> 与深度提示词 `extract_claims.md` 严格分工：本提示词**不产出任何判断**。

## 1. 为什么必须通用

**提示词里不得出现任何领域词。** 一旦出现（例如写「前馈网络」「Linear」「注意力」），会产生两种偏差：

1. 模型看到这类词就以为「要抽这种内容」，换一个领域（法律、医学、历史）就抽不对；
2. 模型把示例的结构当成领域约定，而不是当成**输出格式**。

因此本提示词的示例一律使用**抽象占位符**，不给具体名词。

## 2. 分工：模型只做减法，本地做加法

| 环节 | 谁负责 | 产出 |
|---|---|---|
| 切出「有哪些部分」 | **模型** | 段落列表（标题 + 摘要 + 原文区间） |
| 决定层级（谁是谁的父节点） | **本地算法** | 从标题编号或出现顺序推 |
| 卡片正文 | **本地算法** | 从原文区间**直接截取**，不让模型重写 |
| 交叉链接 | **本地算法** | 按正文词重合度算 |

这样分工的三个好处：

- **零失真**：正文就是原文，模型改不了内容；
- **零幻觉**：模型只需指认「这段属于哪部分」，不必生成事实；
- **提示词可复用**：换任何领域都不改一个字。

## 3. system prompt（原样投喂）

```
你是文本结构化器，只输出 JSON，不解释、不使用 Markdown、不加任何评论。
任务：把用户给的一段文本切分成若干「内容块」，并给每块写一句摘要。

一个内容块 = 原文里连续的一段，讲同一件事。切分规则：
1. 按语义边界切，不要按字数机械切。一个块通常 1–3 段。
2. 每块必须在原文里连续存在，不得跨段拼接、不得改写。
3. 块的数量 1–12；原文很短时只切 1 块。

每块输出三个字段：
- title：这一段讲什么。用原文的措辞，不要自己造名词，不超过 20 字。
- summary：一句话概括，不超过 40 字。只概括，不评价、不补充原文没有的信息。
- bodyStart / bodyEnd：该块在原文中的字符区间（从 0 开始计）。
  bodyStart 必须指向该块第一个字符，bodyEnd 指向最后一个字符之后（不包含）。
  相邻块之间可以有未归属的空白，但**不得重叠**。

硬性约束：
- title 与 summary 用原文的语言书写（原文是中文就用中文）。
- 不要输出任何判断性内容：不写「正确」「错误」「成立」「不成立」「应该」「必须」这类评价。
- 不要输出分类标签、领域名、关键词列表 —— 这些由后续程序计算，不是你的任务。
- 不要合并相隔很远的内容。宁可多切几块，也不要拼成一个块。

输出格式：
{"blocks":[{"title":"...","summary":"...","bodyStart":0,"bodyEnd":120}]}

无法切分时输出 {"blocks":[]}。
```

## 4. user prompt 模板

```
原文（共 {charCount} 字符）：
"""
{content}
"""
```

`{charCount}` 必须给出：模型要输出字符区间，没有总长度它会算错。

## 5. 输出契约

### 5.1 模型返回

```json
{
  "blocks": [
    {"title": "主题A", "summary": "一句话概括", "bodyStart": 0, "bodyEnd": 240},
    {"title": "主题A的子项", "summary": "一句话概括", "bodyStart": 240, "bodyEnd": 620}
  ]
}
```

### 5.2 本地算法加工后的产物

```json
{
  "outline": [
    {"path": "topic-a", "title": "主题A", "level": 1, "order": 1},
    {"path": "topic-a.child", "title": "主题A的子项", "level": 2, "order": 1}
  ],
  "cards": [
    {
      "outlinePath": "topic-a",
      "title": "主题A",
      "summary": "一句话概括",
      "body": "<原文 0..240 的逐字截取>"
    }
  ]
}
```

`outline` 的 `path` / `level` 由本地算法推，**模型不产**。

## 6. 本地算法三件事

### 6.1 层级推断（`OutlineBuilder`）

规则按优先级：

1. **标题编号**：`1` / `1.2` / `1.2.3` / `一、` / `（一）` → 直接按编号深度定 level；
2. **无编号**：按块的先后顺序建立「首块为根、其余为根的子块」的扁平二级结构；
3. **兜底**：全部算一级。

不做自动聚类 —— 把「哪些块是同类」交给模型的分块顺序，比用算法猜更稳。

### 6.2 正文截取（`blockBody`）

```
body = content.substring(bodyStart, bodyEnd)
```

- 越界或倒置的区间**直接丢弃该块**（宁可少一块，不要截出错字）；
- 不 trim 内部，只 trim 首尾空白。

### 6.3 交叉链接（`CrossLinker`）

按正文的**词共现**算：

1. 对每块正文分词（中文按 2 字滑窗 + 英文按 `[a-zA-Z][a-zA-Z0-9_]+`）；
2. 去掉停用词与单字；
3. 两块的共享词 → 相似度 = 共享词数 / 较短块的词数；
4. 相似度 ≥ 0.14 才连边，每张卡**最多保留 5 条**，按权重降序。

阈值 0.14 是经验值：低于它连出来的多是「都提到了某个高频词」这种无意义的关联。

## 7. 调用参数

| 参数 | 值 | 理由 |
|---|---|---|
| temperature | 0.1 | 切分要稳定，重跑不该换一种切法 |
| max_generate_tokens | 900 | 12 块的标题与摘要足够 |
| 输入上限 | 4000 字符 | 更长先分段处理，再合并大纲 |

## 8. 质量红线

| 指标 | 门槛 | 检查方式 |
|---|---|---|
| JSON 可解析 | ≥95% | 复用 `ClaimOutputParser` 的同级解析器 |
| 区间合法 | 100% | `0 ≤ bodyStart < bodyEnd ≤ len`，越界即丢 |
| 区间不重叠 | 100% | 本地校验，重叠部分以先出现的为准 |
| **不生成判断** | 100% | 扫描 title/summary，出现「成立/不成立/正确/错误」即判错 |

最后一条是本提示词与深度提示词的分界线：**广度只讲「讲的是什么」，绝不讲「对不对」**。
